## 拟采用的行为约定

### 阶段 3：统一文件策略

- 由启动入口确定唯一工作区，文件能力和运行请求使用同一个规范化根目录，不能由模型传入另一根目录。
- list/read/search 共享策略：遵守包含嵌套规则的 `.gitignore`，拒绝 `.git`、`.env` 及其变体、常见私钥、越界路径和解析后越界的符号链接。忽略规则不能重新允许这些明确禁止项。
- 仅读取普通 UTF-8 文本，拒绝二进制及特殊文件。读取、遍历、结果数量和总输出均有上限；返回截断标记，不能把部分结果描述为完整结果。
- 用真实临时目录验证相对路径、行号、嵌套忽略与反向规则、符号链接、取消和限额。先完成文件能力的一个切片，再接工具与端到端用例。
- 文件插件提供框架无关能力，LangChain 工具适配器消费该能力；不把本地文件操作塞入应用用例。

### 阶段 3.5：Skill 内容与能力分离

- 显式配置允许的 Skill 根目录；首期使用工作区内目录。SKILL.md 使用 YAML front matter 的 name、description 和 Markdown 正文。
- 发现只返回元数据，按名称加载正文；同名冲突、无效元数据、缺失资料和越界路径明确报错。资料相对所属 Skill 目录解析，继续执行文件访问策略。
- Skill 内容经工具结果进入当前模型上下文，不维护另一份会话历史；加载 Skill 不自动授予写文件或执行命令能力。

### 阶段 4：持久恢复范围

- 提议首个持久后端使用 SQLite 的 LangGraph checkpoint 适配；数据库位于显式配置位置，连接由插件生命周期管理。
- 持久化会话身份、工作区、状态和必要的运行时兼容标识；消息历史仍由 checkpoint 管理。
- 首期可靠续接限定为成功完成的轮次。对运行中崩溃、失败、超时或取消状态提供可观察的状态与明确拒绝，不自动重放未完成调用；可建立新会话继续工作。
- 验证真实独立进程的退出与重开，不仅重用同一个内存对象。数据库不可写、工作区不匹配、重复占用和不兼容恢复均有明确行为。

### 阶段 5：副作用与审批

- 默认只读。写入通过预览变更获得 diff 和版本依据，批准后再应用；检测外部修改冲突，单文件原子替换，不承诺跨文件事务。
- 提议 CLI 默认逐次确认写入和命令。非交互模式默认拒绝，必须通过显式配置批准具体操作范围；模型文本和 Skill 不能自行批准。
- 命令按允许的命令模板选择程序与参数，使用 argv 而非拼接 shell；限定 cwd、环境、输出大小和时间，取消时终止子进程并回收资源。
- 命令允许清单不等于操作系统沙箱：运行仓库测试仍会执行仓库代码。审批中展示实际命令和工作区。
- 已完成变更的重复请求不能重复应用；进程中断后副作用不明时要求结果核对，不自动重试命令。不宣称外部操作“恰好一次”。

### 阶段 6：外部插件和配置组合

- 使用 Python 包 entry points 发现候选插件，YAML 显式启用；发现不自动激活全部安装包。插件提供兼容版本声明。
- 配置组合使用纯数据和确定性的合并规则，验证 include 循环、重复实例、无效路径和冲突。实际规则在本阶段设计中展开。
- 提供可构建安装的独立示例插件包，在隔离环境安装真实 wheel 做验收；测试不以临时修改 sys.path 代替包安装。

### 阶段 7：参考对齐与动态宿主

- 固定参考提交 `46a7f68b0922371ce7144b668b90e377d8e799f4`。逐项覆盖 Cordis 核心、loader 和 HMR 配套；区分框架行为与 Harness 产品能力。
- 静态启动检查与动态等待依赖是不同契约。保留阶段 1 行为；动态接口明确插件实例 ID、作用域、状态和状态转换，不偷偷改变旧接口语义。
- 热替换前暂停受影响的新调用，并等待在途调用结束；超过有界等待期则明确失败，保留可诊断状态。不得在调用中释放其依赖资源。
- 旧实例释放、新实例激活及失败回滚的效果分别验证；外部副作用无法通用回滚，不虚构事务保证。
- Python 不执行 JavaScript 插件或 YAML 表达式。所有与参考语义的差异记入矩阵；实质性差异须确认后才能将完整性验收标为通过。

## 每阶段 review 与发布

1. 保存起始 commit/tag；细化该阶段目标、公开契约和失败行为。
2. 在已确认边界逐条 TDD，记录有效的 red → green 证据；框架本身已支持的行为如实记录为回归验收。
3. review 分别检查项目规范与阶段目标：实现是否正确、是否有缺项、是否越界、失败路径和文档是否真实。问题修复后再执行相关验证。
4. 运行 Ruff、mypy、该阶段验收与前序回归；涉及分发时验证构建和独立安装。真实模型验证显式启用，不将替代模型成功当作真实端点成功。
5. 将 review 发现、修复与剩余限制写入阶段文档。先修复阻断问题，再提交、push 并发布对应 tag；不移动已发布的 tag。
6. 保留阶段 2 B11 的未通过状态；使用已有 `.env` 适时重验。若外部端点阻塞某阶段真实验收，继续可独立完成的工作，明确记录未通过项，不宣称该阶段达标。
