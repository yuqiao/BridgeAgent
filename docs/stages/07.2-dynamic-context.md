# 阶段 7.2：Context 与动态依赖

基线：stage7.1 / 4302c9b。新增 `kernel.dynamic.DynamicHost`，保留静态 PluginHost。

`await host.mount(instance_id, definition, config, context=scope)`：工厂沿用 PluginDefinition，实例 ID 独立于插件名，同插件可挂载多次。`host.status(id)` 返回 pending/loading/active/failed/unloading/disposed 和缺少的服务名称。依赖缺失（包括循环等待）保持 pending，不像静态宿主立即报缺失；可根据缺失快照诊断。

`host.context.isolate(key, label)` 隔离一个服务；省略 label 产生唯一作用域，同 label 可共享，不回退到父级同名服务。`extend(metadata)` 派生元数据；`intercept(key, config)` 与 `config_for(key, base, head)` 提供从父到子合并。没有隐式 Python 属性服务查找。

卸载 provider 会先按逆激活顺序释放依赖者；后者回到 pending，新 provider 到来后自动重激活。激活失败不发布服务，回滚该实例资源，状态 failed；清理所有资源后汇总错误。关闭幂等。当前接口为逐次 await 生命周期操作；在途调用保护和运行中重配置在 7.4。

TDD 证据：tests/test_dynamic_host.py 七个场景依次验证等待→激活、作用域、依赖撤销/恢复、metadata/intercept、重复 provider、失败回滚、取消传播。前五项及取消场景先 red 再 green；失败回滚复用了阶段 1 OwnedContext，作为回归直接通过。

Review：按实际激活顺序释放，不能按配置插入顺序（消费者可先登记）；同作用域重复服务在激活前拒绝；资源协议使用显式方法，不让类型擦除掩盖实现错误。发现取消曾被普通激活错误包装，补测试修复。运行中替换、事件和动态贡献在后续节点验收，此节点不宣称完整 Cordis。

发布验证：210 passed、2 skipped；Ruff、mypy（48 文件）、构建与独立 wheel 的 DynamicHost 导入通过。
