## 交付与使用

动态 CLI 支持 --dynamic、--watch、--entry、/plugins、/reload，保留 /new、/exit、会话查询及原有工具与审批。Agent 应用用例不改变；DynamicAgentRuntime 保护每轮租约并解析当前 entry Context，配置移动/替换后不会继续引用旧作用域。

示例 `examples/dynamic-external.yaml` 无需模型，展示独立插件、多实例、作用域和配置监听；`examples/dynamic.yaml` 装配完整编码工具与 SQLite。详见 [使用指南](../guides/dynamic-plugins.md)。

外部 PluginExport 可选声明 reload_modules/restart_modules；启用插件的 entry point 自动加入 watcher。共享契约/核心变化要求重启；源码清单、Python Context/工厂/Pydantic 的映射已由用户确认，并记录在 [矩阵](07-cordis-matrix.md)。旧静态 v1/API 1 保持兼容。

## Review 结论

逐项对照完整性矩阵、公开测试边界、依赖方向、失败状态和资源归属检查；没有未处理的本地验收失败。本阶段发现并修复：

1. 等待变更时，已有调用的嵌套租约会被写锁阻塞：改为可重入调用组，避免自己等待自己。
2. 清理回调派发异步事件时与生命周期锁互相等待：明确变更窗口内的调用语义，并拒绝子任务在同窗口再次发起生命周期变更。
3. effect 正在获取/释放资源时，卸载未等待完整资源生命周期：获取持租约、释放共用任务且清理受取消保护。
4. volatile 插件显式 reload 被误判成仅更新配置：强制重建。
5. loader 预检未应用配置归一化：统一先 validate_config，再 prepare；避免默认值引起误报。
6. 源码重载丢失 entry 附加 inject 依赖：保留附加依赖，防止服务移除后实例仍 active。
7. 动态 CLI 每轮重新取 entry Context，避免配置移动后继续使用旧 scope。
8. 重复登记源码 manifest 覆盖了共享 contracts 的初始指纹：保留原指纹，确保配置与契约同时变化仍要求重启。

架构仍为 contracts → kernel/application 边界与具体 plugins 分离，bootstrap 负责装配。静态阶段 1 不引入动态语义；动态 host 允许依赖缺失而等待。LangChain 继续是唯一默认 Agent 循环。
