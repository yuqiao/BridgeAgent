# BridgeAgent

面向本地代码仓库任务的可插件化 Agent。以下术语用于本项目的架构与阶段讨论。

## Language

**Agent（智能体）**：接收用户任务，借助模型与工具推进任务并返回结果的执行主体。
_Avoid_：把 Agent 与某一个模型供应商等同。

**Plugin（插件）**：可单独装配并拥有明确生命周期的能力贡献单元，可以提供工具、模型接入、运行时或其他服务。
_Avoid_：将插件仅指工具函数，或与 middleware 混用。

**Tool（工具）**：可供 Agent 调用以获取信息或执行动作的能力，具有明确的输入和结果。
_Avoid_：与插件一一对应；一个插件可以贡献多个工具。

**Agent Runtime（Agent 运行时）**：负责推进一个 Agent 的模型与工具执行过程的能力实现，可通过统一接口替换。
_Avoid_：与插件宿主混用。

**Plugin Host（插件宿主）**：组织插件依赖、激活、贡献注册和资源释放的运行环境。
_Avoid_：将插件宿主称为 Agent 执行循环。

**Capability（能力）**：具有明确接口、提供者和使用者的可替换功能。
_Avoid_：仅凭一个未被使用的接口就声称已实现可替换能力。

**Checkpoint（检查点）**：会话执行过程中可用于恢复的状态记录。
_Avoid_：与聊天记录或执行日志等同。

**Execution Log（执行日志）**：用于观察执行过程和排查问题的运行记录，不是会话恢复的权威状态。
_Avoid_：称为可完整重建模型输入的事件事实源。

**Workspace（工作区）**：一次编码助手运行所指定的代码仓库或目录，是文件工具访问范围的依据。
_Avoid_：与进程当前目录或用户主目录混用。

**Session（会话）**：具有稳定标识、关联连续用户输入与 Agent 执行状态的一组交互。
_Avoid_：与一次模型请求、一次 CLI 进程或执行日志等同。

**Plugin Instance（插件实例）**：一次宿主运行中被配置并激活的插件，拥有这次运行的注册与资源。阶段 1 每种插件只有一个实例。
_Avoid_：与插件定义或独立发行包等同。

**Service（服务）**：插件向其他插件或应用提供、可通过明确身份查找的能力对象。阶段 1 每项服务只有一个提供者。
_Avoid_：与提供它的插件本身等同。

**Service Provider（服务提供者）**：在当前运行中负责提供某项服务的插件实例。
_Avoid_：将消费者固定到某个具体提供者名称。

**Service Consumer（服务消费者）**：需要并使用某项服务的插件或应用。
_Avoid_：将服务依赖与实现包依赖混用。

**Plugin Definition（插件定义）**：描述插件身份、配置验证方式、服务声明与实例创建方式的静态定义。
_Avoid_：与已激活的插件实例等同。

**Plugin Catalog（插件清单）**：显式登记可供配置选择的插件定义的集合。
_Avoid_：把任意 Python 导入路径当作可加载插件名称。

**Service Key（服务键）**：由能力定义方导出的唯一服务身份，关联服务名称与类型，供提供者和消费者共同使用。
_Avoid_：消费者自行创建同名键，或以提供者名称替代能力身份。

**Plugin Context（插件上下文）**：插件访问已声明依赖、贡献服务和登记所属资源的局部边界。
_Avoid_：将其当作可随时操作所有服务的全局容器。

**Activation Plan（激活计划）**：通过依赖与冲突检查后得到的确定性插件激活顺序。
_Avoid_：认为生成计划已经执行插件副作用。

**Owned Resource（所属资源）**：由插件登记、随其生命周期释放的资源或清理动作。
_Avoid_：假定宿主能发现插件私自创建且未登记的资源。
