# 分阶段路线图

状态：所有已编号阶段 0–7 的代码与本地验收已完成，包括 3.5、7.1–7.5。阶段 3 C10 真实仓库问答与阶段 2 B11 工具加法及同会话追问均已通过。阶段 7 最终证据见 [集成验收](stages/07.5-integration.md)。

目标：本地编码助手；学习与实用并重。主线为架构与术语 → 最小插件宿主 → 分层 Agent 闭环 → 只读仓库问答 → 基础 Skills → 持久会话 → 修改与测试 → 外部插件 → 完整 Cordis 风格插件机制。

## 阶段 0：工程基础与架构设计

工程初始化与本轮架构设计已完成。

- 已有：uv、Python 3.13、包布局、静态检查、构建与 CI。
- 本轮交付：参考架构、技术栈、目标分层、阶段路线图、术语、ADR 与决策树。
- 已明确：分层、状态归属、模型接入方向、任务场景、YAML 配置、单 Agent 范围和工作区约束。
- 定稿：按用户最终调整采用 YAML 显式装配；后续各阶段实施前再细化其接口、配置字段与运行策略。

## 阶段 1：能力接口与最小插件宿主

状态：已完成，接口、运行示例与验收证据见 [阶段 1 交付文档](stages/01-plugin-host.md)。

- 交付：同一发行包内的模块分层、YAML 配置与可信插件显式清单、服务注册、启动关闭和资源所有权。
- 可运行结果：无需模型的组合示例，Consumer 通过接口使用 Provider，并可以切换实现。
- 验收：缺失依赖、重复注册、循环依赖明确报错；激活失败回滚已创建资源；关闭后没有残留注册。
- 已启用 CI 行为测试，验证装配替换、资源生命周期、取消与错误；wheel 独立环境运行示例。后续补充 [插件使用指南](guides/plugins.md) 与第三个提供者 reverse，沿用相同接口。
- 已定义类型化服务键、统一 async 生命周期、启动期贡献、单次宿主与错误汇总；第三方包发现、热重载与不可信插件隔离后置。
- 本阶段只交付最小插件机制，不承担完整 Cordis 能力对齐；后者安排在阶段 7。

## 阶段 2：在既定分层中完成 Agent 闭环

状态：实现、本地确定性验收与 B11 真实端点验收均已完成。原 .env 复验完成加法工具结果回传与同会话追问，未改动应用代码或模型配置。逐项标准与证据见 [阶段 2](stages/02-agent-loop.md)，操作见 [使用指南](guides/agent.md)。

- 交付：LangChain 运行时插件、OpenAI 兼容模型能力实现、一个无副作用工具、内存会话、应用用例和 CLI。
- 可运行结果：单工作区、单 Agent 的 CLI 串行多轮交互，每轮可完成输入 → 模型请求 → 工具执行 → 模型总结。
- 验收：更换模型、增加工具无需修改应用层和默认循环；通过替代运行时验证应用接口；验证停止条件、取消和错误返回。
- 确定性测试不依赖真实密钥，真实 API 调用单独验证。LangChain 已接入并锁定版本。
- 模型插件以显式 Chat Completions 模式接入；兼容性验收覆盖标准工具调用和工具结果回传，不只验证普通聊天。流式等能力单独验证，见 [技术栈](tech-stack.md)。
- 使用内存 checkpoint 管理默认运行时的会话执行状态，另记执行日志；不在应用层维护第二份权威消息历史。

## 阶段 3：只读仓库问答

状态：已实现并通过本地 review；2026-09-25 在阶段 7.5 收尾时，C10 真实仓库问答验收通过。详见 [阶段 3](stages/03-workspace-files.md) 和 [使用指南](guides/workspace.md)。

- 交付：文件能力接口、本地文件实现和工具，明确工作区范围，以及执行所需的策略扩展。
- 可运行结果：针对指定仓库的代码问题检索和读取相关文件，回答附有文件路径与行号。
- 首个验收示例：询问一个函数的入口、调用者与行为，答案引用的路径存在，行号对应读取内容。
- 验收：工具通过能力接口访问资源；更换实现不修改工具；列举、检索和读取一致执行 .gitignore、.git/.env/私钥排除、符号链接真实路径与大小限制；覆盖任务成功、拒绝、取消和越界行为。
- 该阶段的注册工具仅提供文本读取、列举和检索，不开放修改文件或命令执行。插件为可信代码，这一限制是工具执行策略，不构成进程级沙箱。

## 阶段 3.5：基础 Skills 支持

状态：已实现并完成本地 review，见 [阶段 3.5](stages/03.5-skills.md) 与 [Skill 指南](guides/skills.md)。真实模型工具端点限制仍独立记录。

- 前置：阶段 1 的插件宿主、阶段 2 的 Agent 运行时，以及阶段 3 的只读文件能力与访问策略；不依赖阶段 7 的完整 Cordis 机制。
- 交付：通过 Skill 插件发现已允许目录中的 Skill，读取名称与描述，按需选择并加载 `SKILL.md` 和参考资料，将指导内容提供给 Agent 上下文。
- 可运行结果：新增一个仓库分析或代码审查 Skill，Agent 按其流程调用已有只读工具，输出带文件位置的分析；新增 Skill 无需修改 Agent 循环。
- 验收：确定性测试覆盖元数据发现、按需正文加载、参考资料读取与上下文传递；验证新增 Skill 可被使用，未选中的 Skill 正文不会全部注入，缺失或无效文件有明确错误。
- 读取 Skill 与参考资料沿用已定义的文件访问约束；本阶段不开放文件修改或脚本执行。需要这些能力的 Skill 在阶段 5 配套支持，不能因加载 Skill 而自动获得额外权限。
- 实施前细化 Skill 元数据格式、发现目录、选择与加载接口，以及重复名称、加载失败的处理规则。

状态：已完成本地验收与 review，见 [阶段 5](stages/05-edit-and-test.md) 和 [修改指南](guides/coding.md)。

- 前置：在引入副作用前，明确工作区写入范围、确认方式、命令执行限制与中断处理。

- 扩展阶段 3.5 的 Skills 支持：允许 Skill 通过已有工具指导文件修改和运行脚本，遵守本阶段的确认、执行范围与中断规则；验收覆盖缺少执行能力或请求被拒绝的情况。

## 阶段 7：完整 Cordis 风格插件机制

状态：7.1–7.5 已实现并完成本地 review。逐项证据及已确认的 Python 差异见 [完整性矩阵](stages/07-cordis-matrix.md)，使用见 [动态插件指南](guides/dynamic-plugins.md)。

根据用户追加要求，将完整插件机制作为阶段 6 之后的明确交付目标，不再仅列为可选扩展。采用独立 Python 实现，以参考基线中的 Cordis 插件框架能力与行为为对齐对象；不承诺直接加载 JavaScript/TypeScript 插件。

- **7.1 能力对齐清单**：基于 [参考基线](reference-architecture.md) 逐项盘点 Cordis 的公开能力、生命周期和失败语义，建立“参考行为 → Python 设计 → 验收测试”矩阵。区分 Cordis 核心、loader/HMR 配套能力和 Harness 产品功能，明确语言映射及差异。
- **7.2 上下文与动态依赖**：实现层级 Context、作用域隔离与服务覆盖，以及依赖出现、消失和实现替换时的激活、停用与重新激活。
- **7.3 事件与可撤销贡献**：实现事件分发、串行/并行、短路和 around-middleware 等语义，统一服务、监听器及其他注册项的资源归属与撤销。
- **7.4 动态生命周期与热重载**：实现运行中插件加载、卸载、配置更新与热重载，明确运行中调用的处理、失败后的宿主状态与资源清理规则。
- **7.5 集成与完整性验收**：用实际 Agent 插件验证 provider 替换、依赖级联、作用域隔离和重复重载；确认没有重复注册或资源泄漏，阶段 1–6 的行为仍通过回归验证。

完成标准：能力矩阵中每项都有实现与测试证据，或明确的 Python 映射及经确认的差异；不能仅凭几个热重载示例宣称完整实现。动态生命周期需要额外的接口版本变化时，提供已有插件的迁移说明。

既有的 YAML 纯数据配置、LangChain 默认执行循环与 checkpoint 状态归属继续适用。参考实现特有的可执行配置语法不自动引入；完整性清单必须显式记录这类差异。该阶段不等同于复刻 DeepSeek Harness 的全部工具、UI 或产品功能，也不自动包含不可信插件的进程隔离。
