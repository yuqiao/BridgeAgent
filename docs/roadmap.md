# 分阶段路线图

状态：设计基线已定稿，阶段 0 完成；阶段 1–6 尚未实现。

目标：本地编码助手；学习与实用并重。主线为架构与术语 → 插件宿主 → 分层 Agent 闭环 → 只读仓库问答 → 持久会话 → 修改与测试 → 外部插件。

## 阶段 0：工程基础与架构设计

工程初始化与本轮架构设计已完成。

- 已有：uv、Python 3.13、包布局、静态检查、构建与 CI。
- 本轮交付：参考架构、技术栈、目标分层、阶段路线图、术语、ADR 与决策树。
- 已明确：分层、状态归属、模型接入方向、任务场景、YAML 配置、单 Agent 范围和工作区约束。
- 定稿：按用户最终调整采用 YAML 显式装配；后续各阶段实施前再细化其接口、配置字段与运行策略。

## 阶段 1：能力接口与最小插件宿主

- 交付：同一发行包内的模块分层、YAML 配置与可信插件显式清单、服务注册、启动关闭和资源所有权。
- 可运行结果：无需模型的组合示例，Consumer 通过接口使用 Provider，并可以切换实现。
- 验收：缺失依赖、重复注册、循环依赖明确报错；激活失败回滚已创建资源；关闭后没有残留注册。
- 在本阶段启用 CI 行为测试；测试应验证装配与替换行为，不只验证空协议或目录存在。
- 实现前明确最小插件协议、依赖表达与关闭语义；第三方包发现、热重载与不可信插件隔离后置。

## 阶段 2：在既定分层中完成 Agent 闭环

- 交付：LangChain 运行时插件、OpenAI 兼容模型能力实现、一个无副作用工具、内存会话、应用用例和 CLI。
- 可运行结果：单工作区、单 Agent 的 CLI 串行多轮交互，每轮可完成输入 → 模型请求 → 工具执行 → 模型总结。
- 验收：更换模型、增加工具无需修改应用层和默认循环；通过替代运行时验证应用接口；验证停止条件、取消和错误返回。
- 确定性测试不依赖真实密钥，真实 API 调用单独验证。LangChain 在此阶段接入并锁定版本。
- 模型插件以显式 Chat Completions 模式接入；兼容性验收覆盖标准工具调用和工具结果回传，不只验证普通聊天。流式等能力单独验证，见 [技术栈](tech-stack.md)。
- 使用内存 checkpoint 管理默认运行时的会话执行状态，另记执行日志；不在应用层维护第二份权威消息历史。

## 阶段 3：只读仓库问答

- 交付：文件能力接口、本地文件实现和工具，明确工作区范围，以及执行所需的策略扩展。
- 可运行结果：针对指定仓库的代码问题检索和读取相关文件，回答附有文件路径与行号。
- 首个验收示例：询问一个函数的入口、调用者与行为，答案引用的路径存在，行号对应读取内容。
- 验收：工具通过能力接口访问资源；更换实现不修改工具；列举、检索和读取一致执行 .gitignore、.git/.env/私钥排除、符号链接真实路径与大小限制；覆盖任务成功、拒绝、取消和越界行为。
- 该阶段的注册工具仅提供文本读取、列举和检索，不开放修改文件或命令执行。插件为可信代码，这一限制是工具执行策略，不构成进程级沙箱。

## 阶段 4：持久会话与可靠续接

- 前置：会话身份和状态语义在阶段 2 已确定，本阶段更换持久化实现并扩展恢复能力。
- 可运行结果：进程退出后重新打开会话，继续约定范围的任务。
- 验收：历史与恢复状态符合约定；明确执行中断和已发生工具副作用的处理；不将 checkpoint 等同于完整日志回放。
- 已确定使用持久化 checkpoint 支持续接，执行日志不驱动恢复；具体后端与恢复点范围在本阶段实施前确定。

## 阶段 5：修改代码与运行测试

- 前置：在引入副作用前，明确工作区写入范围、确认方式、命令执行限制与中断处理。
- 交付：文件修改和测试命令能力，通过接口与独立插件接入现有运行时。
- 可运行结果：完成一个小型代码修改，展示 diff，并执行指定测试验证结果。
- 验收：覆盖写入失败、命令超时、取消和重复提交；恢复时不得在未定义策略的情况下自动重放副作用。具体策略在本阶段设计时确定。
- 本阶段不默认承诺通用操作系统沙箱，也不将“只限制模型工具”描述为隔离可信 Python 插件。

## 阶段 6：独立插件包与配置组合

- 在至少两个真实内置插件验证接口后，确定独立 Python 包的发现、配置和兼容约定。
- 可运行结果：安装、启用一个独立插件包，不修改 BridgeAgent 源码即可执行新增能力。
- 验收：缺失依赖、版本不兼容、无效配置明确报错；退出时正确清理资源。
- 启动时加载外部插件与运行中热重载分开设计，不默认实现后者。

## 后续独立阶段

根据实际任务排序 MCP、Skills、上下文压缩、子 Agent、远程执行、Web UI 与 SDK，不以复刻参考仓库的全部包清单为目标。

## 推进约定

每阶段包含可运行示例、相应测试、文档更新和验收记录。阶段 1 可以不调用模型，但必须展示真实装配和替换；从阶段 2 开始，每阶段用用户可见任务验证新增能力。
