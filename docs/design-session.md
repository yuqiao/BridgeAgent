# 设计讨论

日期：2026-09-25。使用 `grill-with-docs`，按决策依赖逐轮讨论并维护文档。

本文保留最初路线图讨论记录；其中“本轮只做设计”指首次设计会话。阶段 1 的追加授权与交付见文末。

## 已确认

- Python 3.13、最新稳定版 LangChain、uv；本轮只做设计文档。
- Q1：本地编码助手。
- Q2：学习与实用并重，每阶段做出可运行版本。
- Q3：参考 DeepSeek Harness 架构，独立 Python 实现，不承诺原配置、插件或会话格式兼容。
- 补充要求：从第一版建立架构分层，先设计接口与插件宿主，再构建 Agent 闭环。
- Q4：可替换运行时接口 + LangChain 执行循环；模型、工具、会话存储也通过接口装配。
- Q5：可信同进程插件，启动时显式装配；依赖检查、失败回滚、关闭清理首期就有。
- Q6：CLI 作为首个入口，内部应用接口可以复用。
- Q7：checkpoint 管理恢复状态，另记执行日志；先内存运行，后续增加持久化，不承诺完整模型输入的日志重建。
- Q8：先做只读仓库问答，返回文件位置；后续再扩展修改代码与运行测试。
- Q9：首个模型插件接入 OpenAI 或兼容 OpenAI 的服务，具体地址、模型和凭据由运行配置提供。
- Q10：YAML 配置选择显式清单中的插件；地址与模型可配置，密钥仅引用环境变量，配置不执行 Python 表达式。
- Q11：一次 CLI 进程只打开一个工作区、运行一个 Agent；同一会话串行多轮，首期不做后台并发任务和多 Agent。
- Q12：只读工作区内文本，遵守 .gitignore，并排除 .git、.env 与常见私钥；解析符号链接后仍须在工作区内，限制单次读取大小。
- 后续范围调整：完整 Cordis 风格插件机制放到阶段 7；阶段 1 保持最小插件宿主，阶段 6 先完成独立插件包接入。
- Skills 排期：阶段 3.5 实现发现、按需加载与上下文接入，先使用只读工具；阶段 5 支持 Skill 指导文件修改与脚本执行，不依赖阶段 7。
